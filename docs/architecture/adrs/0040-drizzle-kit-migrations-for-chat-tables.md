# ADR-0040: drizzle-kit migrations for the chat session and decision tables

Status: Proposed, 2026-11-03 (RF-07, issue #269).

## Context

Up to 0.7.0, `@agentskit/chat/drizzle-pg` exported `chatSessionDDL` and `chatDecisionDDL` and left migrations to the host (ADR-0036). A later column or constraint change would then need hand-written SQL in every product. The Drizzle tables also omitted the CHECK constraints of the DDL, so a host that put them in its own drizzle-kit schema saw drift against tables created by the DDL.

## Decision

- `chatSessionTable` and `chatDecisionTable` declare the same constraints as the DDL, under the names Postgres gives them (`agentskit_chat_sessions_pkey`, `agentskit_chat_sessions_cursor_check`, `agentskit_chat_decisions_pkey`, `agentskit_chat_decisions_status_check`, `agentskit_chat_decisions_decision_check`). A host can re-export both tables from its own drizzle-kit schema without drift.
- The package ships drizzle-kit migrations in `drizzle/` (generated by `packages/chat/drizzle.config.ts`). The baseline uses `CREATE TABLE IF NOT EXISTS`, so it adopts databases created with the 0.7.0 DDL without changing them. Later schema changes are new drizzle-kit migrations; shipped migrations are never edited.
- `migrateChatSchema(db)` applies them with upstream Drizzle's node-postgres migrator. The journal goes in `chatMigrationsTable` (`__agentskit_chat_migrations`) so it never mixes with the host's own drizzle-kit journal. It reads files, so it runs from a Node deploy step, not from a Worker request. The migrator is imported lazily, so Workers that import the subpath do not load it.
- `chatSessionDDL` and `chatDecisionDDL` stay exported, unchanged.

## Verification

`tests/storage-pg/migration.test.ts` (CI job `runtime-contract`, `pnpm test:migrations:pg`) applies the previous published release's schema step (its `migrateChatSchema` when it has one, the 0.7.0 DDL otherwise) and writes sessions and decisions with that release's stores. It then runs the current migrations twice and checks that every row is unchanged and readable and writable by the current stores, and that the resulting schema equals a fresh migration. `packages/chat/tests/drizzle-migrations.test.ts` fails when the exported tables differ from the last shipped drizzle-kit snapshot.

## Upstream adoption

Inspected: `drizzle-orm` 0.45 `pg-core` (`check`, named `primaryKey`) and `drizzle-orm/node-postgres/migrator` (`migrate`, `migrationsTable`); `drizzle-kit` 0.31 (`generate`, `generateDrizzleJson`, `generateMigration`). Reused: all of these, unchanged. Local: the constraint names, the idempotent baseline, and the separate journal table. No AgentsKit primitive is involved; no upstream work is needed.
